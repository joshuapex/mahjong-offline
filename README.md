# 雀会 · 线下四人日麻战绩

手机优先的私人战绩网站。所有数据需登录查看，支持管理员、记分员和普通玩家。

## NAS 最简部署（推荐）

上传并解压最新源码部署包，在终端进入解压目录，执行 `sh deploy.sh`。已有数据库备份时，将备份命名为 `migration.db` 放在同目录，直接执行 `sh deploy.sh import ./migration.db`，不用先启动空库。默认访问 NAS IP 的 18080 端口，无需手动配置文件权限或 `.env`。空库随机管理员密码见日志，已有账号不会重置。完整说明见 [DEPLOY-NAS.md](DEPLOY-NAS.md)。

此方式使用 `compose.nas.yaml` 和 Docker 命名卷，与下方旧目录挂载方式分开；已有旧部署请先下载完整备份后迁移。

## 功能

- 公共战绩：综合/第 X 届排行、六类指标折线与表格切换、对局列表。
- 我的数据：近期表现对比、净点棒、成绩波动、连续顺位记录、最佳/最低单场、座次表现、个人走势、顺位分布、昵称和密码修改。
- 录入：开局座次、终局点棒、负分、预览结算、草稿、重复提交保护、修改本人记录。
- 管理：用户增删改查、录入权限、密码重置、结算规则列表、LLM、访问地址、日志、CSV 导入导出和数据库备份。
- AI：兼容 Chat Completions API，综合/届次/个人分别手动生成，后台执行，无每日限制。普通玩家查看缓存结果。
- 公网地址：后端检测出口 IPv4，根据外部端口生成链接与二维码，不声称已验证外网可达。

前端为无构建依赖的 HTML/CSS/JavaScript + SVG 图表，后端为 FastAPI + SQLite。全部静态资源本地提供；核心战绩功能不依赖互联网。

## 已有数据

首次运行将 `data/mahjong.db` 使用 SQLite backup API 复制到 `data/app.db` 后迁移，读取已提交 WAL 数据，原始库保留。若已有 `app.db`，不会再次导入原库。

历史中文账号使用通用拼音转换，沿用原密码、用户 ID 和昵称。历史记录按已确认规则从第 1 届编号；历史未记录东风/半庄，迁移默认归为半庄，管理员可更正。

## 本地运行

Python 3.13+：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m app.manage init
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

打开 `http://127.0.0.1:8080`。本地默认 HTTP Cookie；生产 HTTPS 设 `COOKIE_SECURE=true`。

完全空库需要环境变量 `ADMIN_USERNAME`（英文字母）和 `ADMIN_PASSWORD`（至少 10 个字符），没有硬编码默认密码。

忘记历史管理员密码时可在本地终端执行，密码通过交互输入：

```powershell
.\.venv\Scripts\python.exe -m app.manage reset-password YOURUSERNAME
```

## 绿联 DXP4800 / Docker / 1Panel

1. 将本项目目录上传到 NAS，比如 `/volume1/docker/mahjong-offline`。不要上传 `.venv` 和 `test-output`。
2. 若迁移原库，优先在旧服务停服后复制 `mahjong.db` 及其同名 `-wal`、`-shm`；更稳妥的是通过 SQLite backup API 生成单文件快照。不能从运行中的旧库仅复制 `.db`。
3. 复制 `.env.example` 为 `.env`。原库存在时无需设置初始化密码；空库需要设置。HTTP 内网验收时使用 `COOKIE_SECURE=false`；HTTPS 正式访问使用 `true`。
4. 容器用户为 UID/GID `10001`，请仅给挂载的 `data` 目录授予该用户读写权限。Linux 示例：`sudo chown -R 10001:10001 /volume1/docker/mahjong-offline/data`。
5. 在此目录执行 `docker compose build`；在 1Panel 导入本目录的 `compose.yaml` 启动编排，也可执行 `docker compose up -d`。1Panel 编排的工作目录必须与源码目录一致，否则 `build` 和相对数据挂载路径错误。也可在 1Panel 配置为源码、数据目录的实际绝对路径。
6. 内网打开 `http://NAS内网地址:8080`，检查登录、历史记录、届次和录入权限。

只有一个服务、一个公开应用端口，不需要独立 Redis 或数据库容器。使用一个 Uvicorn worker，数据放 NAS 本地磁盘，不放 SMB/NFS 共享。端口冲突时修改 `.env` 中 `APP_PORT`。

### 公网 IP + 外部端口

- 为 NAS 设置 DHCP 地址保留。
- 路由器配置外部端口 → NAS 应用端口或 HTTPS 反向代理端口，并放行对应防火墙规则。存在双层路由时需两层转发；仅有出口 IP 而处于运营商 NAT 时不能直接使用此方式。
- 正式使用登录功能应通过 1Panel 的 HTTPS 反向代理配置证书。IP 地址访问需要与 IP 匹配的证书；选择 HTTPS 本身不会创建证书。可选配置域名以方便证书和动态 IP 管理。
- 「项目管理 → 访问地址」填写协议和**路由器外部端口**，获取当前 IP 并复制链接/二维码。
- 关闭手机 Wi-Fi，用移动数据打开链接，验证玩家登录和管理员录入。IP 改变后重新分享；本功能不更新路由器配置。
- 绿联 UGREENlink 可继续作为管理员进入 NAS 的方式，但它能否代理自建容器需要在实际固件上验证，项目没有依赖该能力。

### LLM

仅管理员可在「项目管理 → LLM 配置」设置 HTTPS 基础地址、模型及密钥。地址例如 `https://供应商/v1`，程序追加 `/chat/completions`。不支持仅提供其它专有协议的接口。

每个综合、届次、个人模块有独立生成按钮。管理员/记分员可生成，普通玩家只看结果；一次只运行一个任务，避免重复开销。数据修改后结果标记过期，昵称修改后通过固定玩家标记动态展示新昵称。模型收到匿名聚合统计和最近 20 场走势，不收到账号、密码或真实昵称。服务重启时未完成任务标记失败，可手动重试。

密钥保存在仅管理员可操作的数据库配置中，读取配置接口不返回密钥；数据库备份含密钥和密码哈希，应保管为私密文件。实际供应商连通性/模型能力需填入配置后验证。

## 数据维护

后台备份是可恢复的单文件 SQLite，下载前去除登录会话，不包含原始 `mahjong.db`。备份副本保存于 `data/backups`；管理员自行按 NAS 备份策略归档。

恢复流程（NAS 项目目录下）：

```sh
docker compose stop mahjong
docker compose run --rm mahjong python -m app.manage restore /app/data/backups/你的备份.db --service-stopped
docker compose up -d
```

恢复前自动保留当前数据库快照，完整性校验后恢复，并清除全部登录会话。文件需先放进挂载目录。不要在运行中的服务上替换数据库文件。

CSV 导入下载后台模板，一行一场：结束时间、四名用户 ID、四个点棒、类型和备注。先预览验证，确认后事务入库。完全相同文件阻止重复导入；不同文件中相同成绩可能是合法场次，因此不自动去重。导出的成绩明细 CSV 为一玩家一行，与导入模板不同。

## 交付包与验证范围

`dist/mahjong-offline-nas.zip` 是可上传 NAS 的纯源码部署包，不包含任何数据库、个人资料、`.venv`、测试产物、缓存或 LLM 密钥。历史数据库保留在本地 `data` 目录，部署时由管理员单独迁移。

本地完成 28 项后端测试、390px/360px 手机及桌面浏览器验证，Compose 格式校验通过。自动化测试使用虚构玩家和场次，不读取个人数据库。当前机器 Docker 引擎未启动，未实际构建镜像；尚未连接 NAS 或真实 LLM 供应商，因此 NAS 运行、外网连通性和实际供应商调用仍需部署验收。

公共和个人折线均使用全体有效历史对局的统一序号；筛选不重编号，累计指标在未参赛时沿用上一值。公共页默认展示所有玩家并提供顺位分布；公共和个人页不提供场次类型或最低场数筛选；综合图表的玩家选择仍使用弹窗。

综合排行榜折线图将玩家勾选收进「走势指标」旁的「筛选玩家」弹窗，可全选、清空或取消。各届折线图隐藏玩家勾选和玩家筛选入口，固定展示该届全部参赛者，不继承综合图表的玩家选择。

排行榜表格移除玩家勾选行，始终展示所选统计范围内全部有有效战绩的玩家，不受综合折线图玩家选择影响。公共表格的排名指标与折线的走势指标双向同步；个人页单场指标独立。

结算规则由管理员统一管理：规则列表支持新增、改名、编辑参数、设为默认、删除；所有统计页、录入预览、对局详情、CSV 导出及 AI 解读统一采用默认项。统计页面不再提供规则选择，也不接受查询参数切换规则。变更默认项时同一批原始对局统一重算，点棒、顺位、场数不变。实际起始点棒固定25000，返还点和 Uma 可修改，Oka 自动计算。删除默认项时自动转移到另一项，最后一套规则不可删除。

公共和个人统计移除场次类型、最低参赛场数、总筛选按钮及筛选弹窗；综合与个人统计全部有效对局，届次排行榜直接在标签处上下滚动选择，默认展示最新一届，移除单独的「选择届次」。综合折线图的玩家筛选入口保留。

我的数据新增同桌玩家比较，按同桌场数排序，逐项展开查看：同桌/未同桌场数、平均成绩、平均顺位、连对率、一位率、四位率、平均净点棒及两组差值；另列顺位领先率和平均终局点棒差。比例差值使用百分点；缺少未同桌样本时不计算差值，一组少于5场提示样本偏少。比较只描述相关差异，不代表因果；分届、时段及其他同桌成员可能不同。个人 AI 摘要包含这些比较，发送时仍使用匿名玩家 ID。

AI 按范围、目标和默认规则 ID 分别保存，并保存生成时的规则参数与数据指纹。规则参数或战绩改变后旧分析标记过期，仅改名不会过期；换默认规则后展示对应缓存。已生成结果与对应综合、届次或个人范围关联。

录入页不显示场次类型与结束时间，新记录默认半庄，实际结束时间由服务器在保存时自动填入（北京时间）。编辑记录保留原结束时间及场次类型；历史导入仍可提供原始时间。

排行榜标签及届次滚轮保持挂载，切换仅更新统计内容并保持页面滚动位置，迟到的数据请求不会覆盖当前选项。「最新」采用独立角标，标题自身居中。
